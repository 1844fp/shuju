# Stack delivery — 2026-11-05

Owned files: infrastructure/start_stack.py, infrastructure/test_stack.py, this document.

Usage from E:/Codex/数据中台: python infrastructure/start_stack.py start; status and stop use the same commands/action. Defaults localhost backend 8000 and frontend 3000; refuses occupied ports rather than restarting listeners. Requires Python psutil (available here 7.2.2), backend runtime dependencies, node and a built frontend/next/.next. No automatic install/build or administrator creation. Default backend initializes schema if needed but does not seed, ingest, recover jobs or replace existing data. Isolated tests: add --backend-port 8123 --frontend-port 3123 --state work/stack-test --isolated to start, same --state on status/stop. Isolated control database, tenant files, PID records and logs remain within project work/. Authentication environment is inherited.

Process records contain freshly obtained PID, creation timestamp and full actual command line. Stop validates all three; never uses historical PIDs, kills by name or adopts listeners. Startup failure cleans up verified owned processes. Windows uses hidden windows; POSIX detached sessions. Timestamp/command mismatch is treated as not owned and is never terminated. This is a local operator tool, not a security boundary against malicious editing of process records. Concurrent start calls are not supported.

Actual Windows validation: start on 8123/3123 with isolated SQLite passed backend /ready and frontend / HTTP200; status showed both running (new PIDs 63048/67620); stop returned successfully; subsequent status [] and socket checks confirmed both ports closed. python infrastructure/test_stack.py: 3 tests PASS (wrong creation time, wrong command, ports closed after integration). No other service stopped. Existing 8000/3000 listener process inventory via Get-NetTCPConnection was denied by OS access permissions, so no claim about their PID/current state is made.

Limitation: Next production rewrites use API_BASE_URL at build time. Alternate backend port does not rewrite existing frontend build; page startup and isolated backend readiness were verified separately, NOT an isolated proxy end-to-end flow. Build frontend separately with API_BASE_URL matching intended backend for that flow, under frontend owner's coordination; this delivery does not alter frontend sources/builds. POSIX logic is implemented but not executed here. Docker executable absent from PATH; Docker validation remains external environment blocker. No Docker installed or system security policy changed. Global runtime tools are used, but all new project files and runtime outputs are under the fixed project directory.
