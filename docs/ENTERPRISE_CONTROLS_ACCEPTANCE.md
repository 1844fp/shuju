# 企业控制与科目贯通验收 · v0.4.0

本轮补齐中台接收控制、企业科目报表映射、ERP数仓来源贯通。项目仍是可运行的全栈工程，企业生产签收尚未完成。所有源码、依赖和验收产物固定在 `E:\Codex\数据中台`。

## 已实现

- `/controls`：按月关闭、按原因重开中台数据接收；版本号比较更新，过期操作409。关闭月份拒绝新增凭证、期初余额、销售、预算/往来登记、银行流水和余额调节输入；原批次重放与既有查询保留。
- 可选严格复核：`FINAGENT_AUTH_MODE=users` 且 `FINAGENT_ERP_APPROVAL_REQUIRED=1`。清洗操作人发起、不同管理员账号查看证据并批准或拒绝；绑定源文件、规则、目录、清洗快照和操作人。未经批准、自己批准、跨组织操作以及旧直接导入绕过均被拒绝。
- `/statements`：组织核准科目明确映射到兼容报表项目；禁止静默重分类。未映射科目返回422，修复此前自定义科目造成KeyError的问题。简化报表新增 `mapping_version`，指标版本 `statement-1.1`。
- PostgreSQL发布：按事实中的核准类别建立企业科目维度，类别冲突回滚；保存字节一致的原始文件、全部清洗行（包括隔离/排除行）、变化、错误与规则版本，并增加文件到事实的血缘。
- 控制审计：真实用户ID或明确演示身份、组织、原因、快照引用和本地哈希链；关键数据接收事件与写入处于同一事务。

## 使用

当前本机演示保留原模式，不自动创建企业账号或开启强制复核。按 `IDENTITY.md` 初始化同组织两个独立管理员账号后，在本地环境中启用上述两个开关并重启服务。仅设置严格开关而没有users身份时拒绝新凭证入库。不能把不同账号视为已证明不同自然人；SSO与职责制度另行落实。

操作顺序：数据源工作台核准科目→上传/只读采集→明确模拟或真实来源→清洗并审查隔离行→清洗人发起复核→另一管理员在企业控制查看证据、填写原因后批准→刷新复核状态→确认入库。复核针对固定快照；重新清洗后须重新发起。拒绝记录不覆盖，不提供撤销已提交数据的功能。

报表需要显式科目映射；科目名不用于自动推断费用、税费或资产类别。账期锁是中台接收控制，不是ERP会计结账，不自动证明报表完整。简化报表仍返回 `completeness=unverified`，须财务人员核准口径。

PostgreSQL在发布前执行 `data_platform/manage.py` 的迁移流程，新增迁移 `003_erp_provenance.sql`；迁移不回填已经发布的旧批次。新原始表不向分析reader授权，只供受控发布身份维护。旧ERP接入批次可通过服务端批次关联查找原始快照。

## 尚未实现或尚未签收

本地哈希链只能检测未同步重写链的内容修改；数据库所有者重写整条链或删除末尾记录，需要外部检查点/WORM存储才能识别。目前无外部不可篡改存证。旧历史审计未回填进新链。审批仅限凭证接收，不是所有主数据/报表/权限变更的全流程审批；尚无审批有效期、撤销、会签与委派。

完整企业级缺口及下一阶段顺序见 `ENTERPRISE_GAPS.md`。本轮通过的本机/隔离PG检查不能代替真实ERP厂商版本、容器部署、SSO、灾备及持续稳定性签收。
